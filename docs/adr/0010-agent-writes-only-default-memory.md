# agent 只写 `default` 那一格；业务空间里的记忆是用户投喂的只读资料

`/memories/` 现在是一棵按业务空间分格的树，很自然会想"在哪格聊就往哪格写"。我们不这么做：
**agent 的写入口只有 `/memories/default/`**，其它格子只能由用户通过 REST（`/memories/write`、
`/memories/upload`）投喂，agent 只读。

这样分是有意的：`default` 是"我这个人"的长期偏好，本来就是 agent 自己维护的东西；业务格子里的
东西是**项目资料**，生命周期跟着项目走，来源是人（导入的文档、记的笔记），让模型往里面写只会
让"这资料是人放的还是模型编的"变得分不清。

代价是**记忆不再跟着会话所在的空间走**：在「项目A」里聊出的结论也存进 `default`，不再落进项目A 那一格。
换来的是写入口唯一（模型不可能把 A 项目的结论写进 B 项目），以及一个字面量路径 ——
prompt 直接写死 `/memories/default/`，不需要先 `ls` 才能知道自己"在"哪一格，也不需要按轮注入
"当前空间名"的 middleware。

静态权限规则能表达"只有这一格可写"，只是因为 `default` 是保留空间名（真实空间不许叫它），
所以 `/memories/default/**` 是个稳定无歧义的静态前缀；换任何一个会变的名字都做不到。

**Consequences**：旧会话里由 agent 写在别的格子里的记忆仍在（按 id 存着），但从此只读；
`/memories/{空间名}/` 下的内容只能从 REST 进，模型想"整理项目资料"得先请人放进去。
