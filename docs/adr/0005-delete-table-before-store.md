# 删公共空间：先删表再清 store，清理失败只记日志

`/public/{名}/**` 的内容在 langgraph store 里，和 `public_workspaces` 表没有外键关系，两次写不在同一个
事务里。顺序必须是**先删表并提交、再清 store**：反过来一旦表提交失败，就是"空间还在、内容已销毁"的真实
数据丢失；而这个顺序下清理失败只留下不可见的孤儿。

清理失败时**仍然返回 204**，只记 `warning` 日志。返回 500 会让调用方以为没删成，重试又拿到 404，
比"删成了 + 日志里有孤儿告警"更混乱。

**Consequences**：`delete` 可能留下孤儿 namespace，这是已知且接受的。要清理就写一条独立的 GC 命令，
别把清理改成事务内或者改成先清后删。私有空间的 `Workspace.delete` 不碰 store，不在这个决定范围内。
