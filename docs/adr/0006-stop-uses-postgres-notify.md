# 停止走 Postgres LISTEN/NOTIFY，不靠负载均衡器

跨进程停止有三条路（对比见下），选了 **B：一张表 + 一条 `LISTEN` 长连接**。

## 为什么不是 A（粘性路由）

A 要**先改造部署**：`uvicorn --workers 4` 是四个进程**共用同一个监听 socket**
（`uvicorn/supervisors/Multiprocess` 里 `Process(self.config, self.sockets)`），
nginx 只看到一个上游地址，连接落到哪个 worker 是内核 `accept()` 决定的 ——
LB 根本看不见 worker，粘不了。得先拆成 N 个单 worker、监听 N 个端口的进程。
而且 worker 重启会同时丢掉粘性和内存表，那一轮就没人收尾了。

## 为什么不是 C（数据库标志 + 图内轮询）

C 能保住“边界停”，但**保不住“立刻”**：middleware 只在节点里跑，只能在超步边界查标志，
`task.cancel()` 在那个瞬间已经没有东西可以打断了 —— 退化成 drain。
而 drain 会在用户卡在一个 60 秒的工具里时**等满 60 秒**，和“用户嫌它跑偏了想叫停”正好相反。

## 为什么不是 C′（图外后台轮询）

C′ 能保住“立刻”（进程级后台 task，不在图里，随时能 `task.cancel()`），
但要么固定 100ms 延迟、要么一直空转查询。B 用推送把它降到 ~1ms 且零轮询。

## 实现要点（踩过的坑）

- `RunControl` / `Runtime.signal`：**langgraph 1.2.11 里没有 `signal` / `AbortSignal`**
  （搜到的博客不可信，以本地源码为准）。`RunControl` 有，但它是**进程内**对象
  （docstring 写明用途是 SIGTERM），不解决跨进程。
- `NOTIFY` 用 `select pg_notify($1, $2)` 参数化，别拼字符串；**payload 上限 7999 字节**
  （8000 直接报错，实测）。所以答案走表的 text 列，不走通知。
- **通知是即发即弃的**：不在监听时发出的会丢（实测）。所以重连成功后补扫一遍表。
  连接断了不会静默失效 —— `notifies()` 会抛 `OperationalError`。
- `NOTIFY` 在同一事务里对相同 payload 会**去重**（实测）—— 对我们无害。
- 控制查询**不能**用那条 `LISTEN` 连接（它在 `notifies()` 里阻塞），也不能借连接池
  （`LISTEN` 是连接级状态）。所以两条专用连接 + 一把锁串行化控制查询。
- 互斥没用 `advisory lock`：它是**会话级**的，要占一条连接**整个轮次期间** ——
  聊天服务主要在等 LLM，那等于把连接池拿去干等。表的 PK 一个 `INSERT` 就够。

## 两个真实的代价

1. **owner 挂了，请求方要等满超时**（`STOP_TIMEOUT + 1s`）。表里那行还在但没人认领，
   请求方分不清“别人在跑”和“owner 已经死了”，只能等。之后自己兜底收尾，记 `warning`。
   这就是 `docs/adr/0004` 里记的那个脏写风险 —— 概率低但没法根除。
2. **心跳回收有个窗口**：listener 每 5 秒给自己在跑的轮次打一次心跳，
   超过 `TURN_HEARTBEAT_TTL`（60 秒）没心跳就当那个 worker 挂了，把那行清掉。
   所以 worker 崩溃后，那个会话最多 60 秒不能开新轮次。TTL 太短会在 listener 重连时
   误伤还在跑的轮次（那就丢掉互斥了），太长则恢复很慢。

## 顺手修掉的一个老 bug

**孤儿轮次**：owner 在轮次跑到一半时挂掉，检查点停在半路，没有任何人会收尾它 ——
下一条消息会和那条没回答的 human 消息**合并成一次请求**（实测模型看到
`[system, human:甲, human:乙]`，只回一条）。这个 bug 单进程就有，多进程更容易触发。
现在 `ChatService.open_turn` 在开新轮次前先看一眼检查点，是半路就复用 `astop` 收尾
（靠 `astop` 自己的幂等，已经跑完 / 正等人批准时它什么都不做）。

## 被否掉的备选

- **请求方自己收尾**：它没有 `turn.text`（已流出的文本只在 owner 内存里），
  而且不知道 owner 什么时候真的停了 —— 会重新引入那个脏写。所以是 **owner 收尾**，
  结果写回表，请求方轮询读走。
- **反向通知通道**：请求方本来就要等，轮询一个已知行比再养一套通道简单。
