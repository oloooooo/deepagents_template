# 停止是「把这一轮就地收尾」，不是撤销

用户按停止时，图正跑在中途，检查点停在半路（`next` 非空）。**不收尾的话下一轮会出错**：
如果停在模型生成中途，检查点里只有一条没有回答的 human 消息，下一轮的新消息会和它
**合并成一次请求**（实测模型看到的是 `[system, human:甲, human:乙]`，只回一条）——
用户以为甲作废了，其实甲还躺在历史里。

所以停止的收尾是**就地把这一轮写到终点**，走 `AgentMemory.astop`：

1. 把**已经流出的增量文本**补成一条 AI 消息（用户已经看到的字不能凭空消失）；
   一个字都没流出来时用 `（用户停止了本轮）` 占位，让模型知道这里断过；
2. 如果最后一条是只有 `tool_calls`、没有文本的 AI 消息（工具执行中途被停），先删掉它，
   否则前端会渲染出一个空气泡；
3. `aupdate_state(..., as_node="model")` —— 让 langgraph 把这次写入当成 model 节点的产出，
   于是从 model 重新路由，没有 tool_calls 就走到终点、`next` 清空；
4. 再 `ainvoke(None)` 排空剩下的待执行节点（正等人批准时 `next` 停在
   `HumanInTheLoopMiddleware.after_model`，上一步只清掉了待批准请求）。

**不做的事**：不回滚已经发生的副作用。工具已经写过的文件、已经落库的 `/memories/` 都留着 ——
停止是「到此为止」，不是「撤销」。要撤销得另外做，而"撤销一个已经执行完的副作用"在
有任意工具的情况下根本不通用。

**Consequences**：历史里会出现 `（用户停止了本轮）` 这种占位消息，而且它是真的 AI 消息
（模型下一轮会读到）—— 这是有意的，比留一条无回答的 human 消息或空消息好。
